## Über uns

BK One ist eine **digitale Firma im Betriebssystem-Format**: 50 Rollen, 23 spezialisierte
Agenten, eine schriftliche Verfassung. Jeder Auftrag durchläuft 12 dokumentierte Schritte
und sieben unabhängige Qualitäts-Gates, bevor er ausgeliefert wird. Wir versprechen
keine Magie — wir versprechen **Wiederholbarkeit, Auditierbarkeit und Ruhe.**

## Arbeitsweise

> Die Kernschleife — zwölf Schritte, in dieser Reihenfolge, jedes Mal.

```
   1. Inbox-Watch           →  Drop in inbox/ wird erkannt
   2. Triage                →  Ticket angelegt, klassifiziert
   3. Kickoff-Meeting       →  Departments parallel briefen
   4. Rückfrage (optional)  →  E-Mail an Sie, Ticket pausiert
   5. Spec & Design         →  Akzeptanzkriterien, Wireframes
   6. Implementation        →  Frontend/Backend/DevOps parallel
   7. Gate A                →  QA · Security · Quality   (alle PASS)
   8. Gate B                →  Regression · Privacy · Compliance · UX
   9. Release               →  v1.2.3, Hash-Manifest, read-only
  10. Lieferung             →  E-Mail mit Versionsdetails (deutsch)
  11. Archivierung          →  Audit-Spur, Retro, Decisions-Update
  12. Zurück zu Schritt 1.
```

**Was bedeutet das für Sie?** Sie werfen einen Auftrag in den Briefkasten —
formloser Text reicht. Wir melden uns mit Rückfragen oder direkt mit dem Spec.
Sie hören erst wieder von uns, wenn ein versioniertes Release zur Abnahme bereitsteht.

## Qualität

> Ein Release passiert sieben unabhängige Gates. Eines fällt durch — das ganze Release fällt durch.

<table width="100%">
  <tr>
    <td><b>A1 · QA</b></td>
    <td>Unit, Integration, E2E. Coverage ≥ 80 %. Keine flaky Tests.</td>
  </tr>
  <tr>
    <td><b>A2 · Security</b></td>
    <td>OWASP Top 10, Secret-Scan, Dependency-CVEs, Authz-Review.</td>
  </tr>
  <tr>
    <td><b>A3 · Quality</b></td>
    <td>Architektur-Review, unabhängiger Code Review, UX-Heuristik.</td>
  </tr>
  <tr>
    <td><b>B1 · Regression</b></td>
    <td>Volle Regressions-Suite im Staging, Performance im Budget.</td>
  </tr>
  <tr>
    <td><b>B2 · Privacy</b></td>
    <td>DSGVO, Datenminimierung, Consent, Retention, Auskunfts-/Löschrecht.</td>
  </tr>
  <tr>
    <td><b>B3 · Compliance</b></td>
    <td>Lizenz-Kompatibilität, Dokumentation vollständig, Audit-Spur unverändert.</td>
  </tr>
  <tr>
    <td><b>B4 · UX-Abnahme</b></td>
    <td>Jedes Akzeptanzkriterium aus dem Spec verifiziert. WCAG 2.2 AA.</td>
  </tr>
</table>

**Unsere Versprechen:**

- Produktion ist **unveränderlich**. Jedes Release liegt in einem eigenen versionierten Ordner mit SHA-256-Manifest.
- Drift wird **bei Session-Start automatisch erkannt** und protokolliert.
- Nur **eine einzige Rolle** darf in den Produktionsordner schreiben — der Release Manager.

## Standards

> Was Sie von uns erwarten dürfen — schriftlich.

| Bereich | Standard |
|---|---|
| **Barrierefreiheit** | WCAG 2.2 AA (Minimum) |
| **Performance** | LCP &lt; 2,5 s · INP &lt; 200 ms · CLS &lt; 0,1 |
| **Code-Qualität** | ≥ 80 % Testabdeckung auf geändertem Code, keine flaky Tests |
| **Sicherheit** | Keine Secrets im Quellcode · Eingabevalidierung an Grenzen · Rate-Limiting |
| **Datenschutz** | DSGVO-konform, Datenminimierung, 30 Tage Default-Retention |
| **Commits** | Conventional Commits (`feat:`, `fix:`, `chore:`) |
| **Sprache (intern)** | Englisch |
| **Sprache (Kundenkontakt)** | Deutsch, Sie-Form |
